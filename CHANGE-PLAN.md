### CP-33 · Strict, nonce-based CSP (not urgent, revisited 2026-10-06)
- The baseline CSP (`next.config.ts`, added 2026-09-28) keeps `script-src`/`style-src` `'unsafe-inline'` because App Router RSC streaming and framer-motion inline styles need it. A stricter CSP needs a per-request nonce generated in `proxy.ts`, forces every page into dynamic rendering (no static generation/ISR/CDN caching), and `style-src` likely stays `'unsafe-inline'` anyway (framer-motion mutates the `style` attribute directly, which a nonce doesn't cover) — a real architecture change, not a config tweak.
- Checked 2026-10-06: `grep` across `src/` finds zero uses of `dangerouslySetInnerHTML` or `innerHTML` — React escapes all rendered content by default, so there is currently no known injection point for an attacker to get a `<script>` onto the page in the first place. `'unsafe-inline'` today is a dormant defense-in-depth gap, not an active, exploitable hole; it would start to matter if a future change adds something that renders raw HTML (a rich-text comment field, a markdown renderer, a third-party widget). Owner's call: not worth the static-rendering trade-off while that's hypothetical — kept as a low-priority "needs a plan" item, not declined outright, revisit if the app ever grows an HTML-rendering surface.
