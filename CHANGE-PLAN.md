### CP-8 · Production: choose the public MinIO address and set `S3_PUBLIC_URL` (added 2026-09-23; blocked, no domain or server yet)
- Uploads store the full image URL in the database, built from `S3_PUBLIC_URL`. The variable is required everywhere (`env.ts` refuses to start without it, there is no fallback to `S3_ENDPOINT`). In production set it when the address is known, for example `https://media.<domain>` (the value is the MinIO root, the bucket name is appended).
- The address must be stable: changing it later means rewriting the stored URLs (`UPDATE media SET original_url = replace(original_url, '<old>', '<new>'), thumbnail_url = replace(thumbnail_url, '<old>', '<new>')`). Coolify's temporary generated domain is a poor choice for this reason.
- Locally the value is the same as `S3_ENDPOINT` (`config/local.env` already has it).

### CP-16 · Two findings from the media-upload-limits discussion (found 2026-10-02, not yet fixed)
- a) `next.config.ts` doesn't set `experimental.proxyClientMaxBodySize` (Next defaults to 10 MB), so any request body over that — including an upload near/over `NEXT_PUBLIC_MAX_FILE_SIZE_MB` — is silently truncated and fails with a raw 500 instead of a clean error. Confirmed reproducible (a 12 MB file, and two 8.7 MB files in one request, both failed this way). Fix: set the option to `NEXT_PUBLIC_MAX_FILE_SIZE_MB` plus some headroom. This is a `next.config.ts` edit, so it needs your explicit go-ahead.
- b) `admin/media/page.tsx` bypasses RTK Query (raw `fetch` for upload/delete), so it has none of the silent-token-refresh, cache-invalidation or per-file-error behavior the rest of the admin UI gets. You asked for a Telegram-style rework instead: select many files, each uploads and shows its own queued/uploading/done/error status, "Save" blocked while anything is in flight, a failed file visible with its own error instead of a toast. To be scoped as a fresh numbered-issue list when this round starts, same as 26–30.
- Neither item is fixed yet; both are recorded with full detail in `PRODUCTION-READINESS.md` → Input validation and `DEVIATIONS.md` → Media / Frontend (Admin) so a future session doesn't have to rediscover them.
